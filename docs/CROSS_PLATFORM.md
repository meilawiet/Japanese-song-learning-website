# Windows / Android 跨端互通

实现依据：用户提供的《UTA-跨端数据协议-2026-10-19》，云容器 v3、歌曲目录 v2、学习核心 v1。产品版本号不能代替协议版本。另一端同样需要支持这些协议版本，不能仅凭安卓产品版本号认定兼容；本次没有修改安卓分支，也未完成兼容 APK 的真机往返验收。

## 使用

1. 在 Windows 的“设置 → 跨端互通”填写 HTTPS WebDAV 目录、账号与应用密码，保存配置、测试连接。安卓填写同一目录；上级目录需已存在，UTA 可创建最后一级目录。
2. 在作为资料来源的设备点击“上传本机快照”。首次传音频，以后只补传缺失的原始音频；改歌词、封面或学习记录不会重新上传同一音频。
3. 另一端刷新云端快照列表，下载并预览，核对歌曲、学习记录和 AI 配置范围，然后确认恢复。恢复会替换整份本机资料，不做自动双向合并。
4. Windows 先保存本机恢复点，再恢复完整歌词和学习资料。同 ID 且实际大小、SHA256 均匹配的音频直接复用，其余音频在该设置页按歌曲下载。纯歌词歌曲无需下载；未设置时间的句子可以学习和编辑，但不能按句定位播放。
5. 下载失败可重试；传输过程可取消。恢复进入本机提交阶段后不能取消，请等待完成。网络异常不会自动删除云文件。

API Key 默认不上传；每次选择包含密钥都会再确认。恢复时可选“保留本机 AI 配置和密钥”（Windows 默认）或“使用快照中的 AI 配置”（快照无 Key 时会清空本机 Key）。这是 Windows 的显式选择，不表示旧安卓已经采用相同默认策略。云快照本身没有内容加密；WebDAV 密码只在本机 Windows 加密存储中保存。

主题、字体、字号、窗口布局、托盘偏好和完整的快速打开顺序留在 Windows。按歌语言、注音方式、译文开关、来源/人工注音开关、罗马音位置与绝对时间覆盖按协议保存和使用。Windows 自有的隐藏词注音只在原句、词索引、词面和读音仍匹配时保留，不向安卓假定扩展字段支持。

Windows 内置词典仍只负责日语自动注音。互通的其他语言歌曲保留原文、来源/人工标注和已保存资料，不会交给日语词典重新生成。此接口不等于移植了安卓的全部多语言学习功能。

## 数据与恢复约定

- 云文件：`_uta-audio-<sha256>.bin` 是原始音频；`UTA-<UTC时间>-<标识>.uta-backup` 是完整非音频资料。每次新建快照，`PUT If-None-Match: *`，不覆盖或清理历史文件。
- 网络在 Electron 主进程进行；渲染进程只调用受限 IPC。仅 HTTPS、Basic 认证、白名单文件名；不跟随重定向。目录使用 PROPFIND，不用 HEAD 猜测音频大小。
- 音频经 256 KiB 分块暂存、流式 SHA256、限额校验。下载在完整大小及摘要正确后才写入歌曲库。切换云目录后，待下载引用不能直接迁移；需先从原目录取得真实音频。
- ID、原文、词元、空人工读音、字面注音、时间原点及共享学习字段保留。相同音频不代表相同歌曲，不按歌名或音频自动合并记录。
- 跨库恢复涉及歌曲库、学习状态、头像、对话和加密凭据，不是单一数据库事务。先写入完整恢复点与持久恢复日志，失败后回滚。中断时下次启动显示恢复提示，暂停后台学习状态写入；从“数据管理”选择恢复点恢复。旧 AI 配置在中断恢复期间另存于 Windows 加密文件，不写明文 Key 到恢复点。
- 现有本地学习备份 v1 继续可读。有纯歌词、待下载歌曲或空时间的新本地备份使用本地 v2；这不是云协议版本。互通云文件内仍始终使用空 songs 的核心 v1。
- 跨端设置明确拒绝旧云版本。普通数据管理仍能恢复旧本地备份和本机完整恢复点；不能把只含音频引用的云目录文件冒充完整离线备份。
- 限制：单个云文件 500 MiB、云头及核心 JSON 各 16 MiB、头像 10 MiB、1000 首歌曲、每首 2000 行。未知合法附加字段尽量保留，但安卓歌曲根字段采用白名单，未共同约定的 Windows 扩展不能承诺任意往返。

## 接口定位

| 模块 | 责任 |
| --- | --- |
| `src/components/DesktopCrossPlatformPanel.jsx` | 设置、快照列表、预览、AI 范围、进度、取消、按首下载 |
| `src/lib/desktopCrossPlatform.js` | 固定上传资料视图、原始音频去重、恢复点、恢复与回滚 |
| `src/lib/cloudAudioCatalog.js` | 目录 v2、音频引用、仅音频复用、共享与设备偏好分离 |
| `src/lib/cloudBackup.js` | v3 外层解析、空核心校验、个人资料/对话/头像校验 |
| `desktop/webDav.cjs` | 受限网络、加密凭据、分块暂存、摘要校验、持久恢复日志 |
| `desktop/main.cjs` / `desktop/preload.cjs` | 可信窗口校验及 WebDAV IPC 桥 |

调用 `window.utaDesktop.webDav(action, payload)`：连接 `load/save/clear`；网络 `directory/stat/upload/download`；暂存 `begin/append/digest/read/release`；取消 `cancel`；本机恢复 `recoveryStatus/restoreBegin/loadRecoveryAi/restoreFinish`。暂存只返回随机会话 ID，不接受任意本机路径；恢复点只接受应用自动生成的名称。`onWebDavProgress` 提供字节进度，服务器确认后才视为上传成功。

## 验证边界

使用附件原创样例和隔离的实际 Windows EXE 验证，没有复制真实用户歌曲或使用真实账号。网络由本机模拟 WebDAV 提供，测试期间注入传输目标，生产代码的 HTTPS 与证书校验没有放宽。Windows 加密凭据在实际 EXE 中验证。

覆盖协议字节长度、纯歌词、null 时间、稀疏 ID、人工空读音、按歌设置、重复音频、未知长度、HTTP 错误、重定向、取消、同长损坏、恢复回滚、中断重启、同音频新歌词及旧备份读取。

**尚未验收：真实公网 WebDAV 服务、对应新格式安卓 APK、Android→Windows→Android 的真机往返。** 不能以附件自检、模拟服务器或 Windows 单端检查代替双端验收。自动双向合并、冲突处理、远端删除同步和云端垃圾清理不在本协议中，本次未加入。
