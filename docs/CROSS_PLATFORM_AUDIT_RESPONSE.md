# 数据互通审查：安卓侧修复回应

日期：2026-10-19。依据：电脑端提供的《互通可行性与实施方案.md》及安卓当前开发代码。本文只记录安卓侧核对和实际修复，不表示 Windows 已经适配或双端同步已验收。

> 发行状态补充（2026-10-22）：下文是 10 月 19 日的审查记录。所述安卓侧修复及音频独立格式随 Android 1.6.0 发行，最新字段以[跨端协议说明](UTA_CROSS_PLATFORM_DATA_PROTOCOL.md)为准；历史验证范围不因发版扩大。

## 已确认并修复的共同问题

协议允许复习条目最少只有 `songId`、`lineId`。安卓原来的 `reconcileLearningState` 与电脑端报告的行为一致：还要求 `line.text === item.text`，因此没有 `text` 的合法条目会在重整时被删除。

修复前已用新云快照的实际写入、读取和学习状态重整链路复现；并验证了纯歌词恢复、已有本地音频复用、待下载音频补齐等路径。

### 修复后的规则

1. 精确匹配歌曲 ID 和歌词行 ID，不按原文相同、文件名或数组下标猜测。
2. 记录缺少 `text`，且稳定本机歌曲身份或已有快照/注音原文能够确认此行时，补齐当前原文；保留其他记录字段，不修改输入对象。
3. 已有显式 `text` 仍须与当前原文完全一致。原文变化、行 ID 不存在等情况继续遵守原有失配清理，不能靠省略字段绕过原文身份核对。
4. 待下载音频的条目先保留，音频补齐后执行相同核对；重复副歌必须以各自行 ID 区分。
5. 当前库找不到的其他歌曲引用保持不变，不映射到同名歌曲。

没有添加新的数据字段或修改 cloud=3 / catalog=2 / core=1。本文没有声称已实现无法对应记录的待处理界面；保留全部冲突的隔离机制属于后续协作范围。

源码：`src/lib/learningIdentity.js`。回归：`tests/reviewItemInterop.test.mjs`。协议对接文档第 6.1 节已补充上述消费语义。

### 已完成验证

- 修复前新增的 4 项回归检查均能复现条目丢失；修复后通过，全套自动检查 **247/247**。
- 云快照实际写入→读取→学习状态重整→再次备份后保留最小条目，保持附加字段、输入不可变及重复执行结果稳定。
- 覆盖纯歌词、已存在音频、待下载音频、稀疏行 ID 和重复原文；显式错误原文及已有证据表明歌词改变的行不会被误关联。
- Chromium 89 真实页面配模拟原生 WebDAV 桥：恢复后的 3 条复习记录全部保留，缺少音频的一条先不补原文，音频下载后补齐；重启和再次上传后仍保留。未使用真实云盘或用户歌曲。

## 文档其他差异在安卓侧的情况

| 审查项 | 安卓当前开发实现 |
| --- | --- |
| Windows 不支持新云 v3 / 目录 v2 | 安卓新开发代码已支持；公开 Android 1.5.2 仍使用旧云格式，这是版本能力差异，不应只修改 Windows 的版本判断 |
| 纯歌词 / 待下载音频 / null 时间 | 安卓已有明确区分，加载本地音频前检查 Blob 和下载状态；纯歌词可恢复和使用 |
| songSettings 保存 | 安卓当前的状态保存和云核心导出已包含该字段；桌面新扩展字段仍需双方协商接入，不保证任意未知字段往返 |
| none 注音偏好 | 安卓备份校验和显示归一化均已接受 |
| 人工空读音、literal 注音 | 安卓已有空字符串优先及按原样显示逻辑；恢复不应重分词后套用旧词元索引 |
| 项目歌曲覆盖对象、译文限制 | 安卓接受已有协议所列对象与限制；桌面需区分项目覆盖和本机歌曲 lines，不直接挪用时间字段 |
| AI v2 及等级绑定 | 安卓已有原文/行 ID/绑定版本/日语等级校验；现存记录不能直接补版本标记冒充校验结果 |
| 音频 SHA256 | 安卓新格式对原始音频独立寻址，下载校验完整 SHA256；本地旧核心仅有长度检查不能替代此流程 |
| 自动双向合并、跨端锁、删除事件 | 尚未实现；本次未将审查中的实施建议作为已完成能力 |

Windows 当前分支及 EXE 没有在本次修改。协议建议先由双方各自补适配层，再进行 Android→Windows、Windows→Android、往返三轮真实交叉验证。
