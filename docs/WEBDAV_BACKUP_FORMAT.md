# WebDAV 音频独立备份格式（Android 1.6.0）

<!-- 原说明为尚未发布的本地开发格式；1.5.2及更早版本使用整曲附件。 -->
此格式随 Android 1.6.0 提供。1.5.2 及更早版本使用旧的整曲附件格式。Windows 分支需另行适配本协议，不能直接宣称已经互通。

给电脑端开发者的完整字段、二进制偏移、记录身份及联调清单见[UTA 跨端数据协议对接说明](UTA_CROSS_PLATFORM_DATA_PROTOCOL.md)。本页保留为音频拆分格式的简要说明。

## 文件组成

| 文件 | 内容 | 复用规则 |
| --- | --- | --- |
| `_uta-audio-<SHA256>.bin` | 原始音频文件字节 | SHA256 仅由音频字节决定，与歌曲编号、文件名、MIME 类型和所有非音频资料无关 |
| `UTA-<时间>-<随机标识>.uta-backup` | 一次完整的非音频资料快照 | 每次上传生成新文件，最后提交；不覆盖历史快照 |

快照包含歌曲名称、歌手、封面、完整歌词、翻译、来源注音、时间戳、时间戳重置原点、学习记录、个人资料、头像、对话及 AI 配置。API Key 仍默认排除，WebDAV 凭据永不进入快照。

## 格式标记

- 外层签名：UTF-8 `UTA-CLOUD-BACKUP\n`。
- 签名后：4 字节无符号小端整数，表示 JSON 头长度。
- JSON 头 `version: 3`，必须含 `catalog.version: 2`。
- 头后依次为 `coreSize` 字节的学习记录核心、`avatarSize` 字节的头像。核心歌曲数组为空，不含音频。
- 外层 v1/v2 和目录 v1 不再兼容。遇到旧云备份，提示从当前版本重新上传，不尝试迁移或修改云端旧文件。
- 本地学习数据导出/电脑传歌使用的核心解析器属于独立流程，本次未重写其格式。

目录条目示例：

```json
{
  "version": 2,
  "songs": [{
    "id": "local-example",
    "title": "原创练习",
    "artist": "UTA",
    "audioName": "example.wav",
    "lyricsOnly": false,
    "lines": [{
      "id": 0,
      "start": 1.2,
      "timestampOriginalStart": 1,
      "text": "原创短句",
      "translation": "",
      "romaji": ""
    }],
    "audio": {
      "name": "_uta-audio-<64位小写十六进制SHA256>.bin",
      "sha256": "<64位小写十六进制SHA256>",
      "size": 12345,
      "type": "audio/wav"
    }
  }]
}
```

纯歌词条目必须明确 `lyricsOnly: true`、`audio: null`，不生成音频文件。没有时间戳的行保留 `start: null`。

## 上传

1. 对本地原始音频流式计算 SHA256，检查云端同名文件。
2. 存在且大小正常时复用；不存在时上传。音频字节改变会产生新文件名；修改歌词、时间戳、封面或文件名不会产生新音频附件。
3. 已恢复但尚未下载的音频仅可在原云目录复用，必须确认远端存在；禁止凭缺失的本地音频迁移到其他目录。
4. 音频全部成功后，上传包含所有非音频资料的新快照。失败时不提交快照，释放临时文件。
5. 不自动删除云文件；手机删除歌曲后，新快照不再引用它，旧快照及音频仍保留。

音频上限为单文件 500 MB，快照 JSON 头上限 16 MB，目录最多 1000 首。相同音频可以被不同歌曲条目、不同历史快照共同引用。

## 恢复与下载

- 下载快照并预览，用户确认后恢复完整歌词、时间轴和学习资料。
- 本地同编号歌曲已有音频时，计算实际音频摘要；匹配则保留本地音频，同时应用快照中的新歌词和其他资料，不能复用旧歌词。
- 没有对应音频时建立待下载记录，但完整歌词已经保存在本机。按首确认后，仅下载音频，校验大小及完整 SHA256，再装配进该记录。
- 纯歌词恢复后直接可用。任何恢复写入失败仍按原事务流程回滚本机记录。
- 不根据歌名或同样的文件大小猜测音频相同，也不根据设备时间判断哪个内容更新；当前功能仍为快照备份恢复，不是自动双向合并。
